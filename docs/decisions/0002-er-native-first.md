# ADR-0002: ER図は編集可能なネイティブ図形を原則とし、複雑な場合のみSVGへフォールバックする

- 日付: 2026-10-11
- 状態: **Accepted（プロジェクト所有者が方式Aを選択）**
- 関連Issue: #19, #10, #11, #22
- ADR-0001の原則（内容/デザイン分離・決定論的レンダリング）を維持し、ER図の「v1はSVG」方針のみ本ADRが優先する。

## 課題

現行 `type: er` はノード名と接続を箇条書き状に表示する `diagram-as-text` フォールバックであり、ER図の主要情報（エンティティ、属性、キー、カーディナリティ）を構造的に表示できない。一方で図全体を無条件にSVG画像とすると、技術図・表をPowerPointで編集できることを重視する本プロジェクトの要件と衝突する。

## 決定

1. **ネイティブ優先**。通常のER図は、エンティティ枠・属性欄・PK/FK表示・リレーション線・カーディナリティをPowerPointのネイティブ図形/文字/線で出力する。文字と線の選択・変更・保存ができることを検査する。
2. **意味は必ず `content.yaml` に保持**。ERのエンティティ、フィールド、キー、関係、方向、多重度を構造データとして記録する。デザイン担当はこれらを変更しない。
3. **データ契約は互換追加**。現行の `schema_version: '0.1'` と `diagram.nodes/edges` を壊さず、`docs/schema-versioning.md` に従って v0.2 等への互換追加を行う。属性/型/PK/FK/nullable/関係の多重度を失わない変換と逆写像テストを追加する。正確なフィールド名・正規形は #19 の実装PRで策定し、旧入力の回帰試験を残す。
4. **SVGは例外**。決定論的なネイティブ配置で読みやすさと非重なりを満たせない高密度図だけ、構造ソースからSVGを自動生成して埋め込む。切り替えを黙って行わず、`fallback_reason`・図のSlide ID・元ソースのハッシュ・画像化された対象をmanifestに残す。
5. **SVGでも再生成可能性を保証**。画像を唯一の正本にしない。構造データから再生成でき、フィールドや関係の欠落と出自を検証できること。SVG出力時はPowerPoint上の**図内部は画像であり個別編集できない**ことを明記する。
6. **通常資料のPDF表示とWindows PowerPointの編集性を別々に評価**。LibreOffice/PDFでの成功はWindows版PowerPointの互換性を保証しない。所有者がWindows版PowerPointを利用できるため、#10で実機確認を行う。

## フォールバック判定のルール

- 閾値は実測ベンチマークから決める。エンティティ数だけで判定せず、属性行数、表示テキスト幅、辺の接続・交差、スライド密度、文字サイズを組み合わせた**再現可能な**判定を定義する。
- レイアウトアルゴリズムはサイズや表現の調整・複数スライドへの分割案を優先する。安易に小さい文字へ縮めない。
- ネイティブ配置が安全に成立しない場合の振る舞いは、ユーザー指定の `native_only` / `auto` / `svg` 等のポリシーを設計側で明示し、`native_only` は失敗を返す。新規スキーマフィールドの詳細は #19 で決める。
- SVGへ切り替えた場合は画像内テキストの編集可能性をPASSと偽らず、Gate 2の例外として一覧化する。**未検証の自動SVG変換や静かなテキスト表への後退は許可しない。**

## 受け入れテスト

- 4〜6エンティティ程度の小規模ER（複合PK、FK、1:N、任意関係を含む）をネイティブ出力し、PPTXのXMLとWindows PowerPointで各部品が編集できること。
- 高密度ERの検体を用意し、ネイティブの可読性・配置品質を判定する。SVGへ切り替える場合は理由・編集不可の範囲・正本との対応が報告されること。
- 原データ→adapter→出力（ネイティブ/SVG）でノード・属性・関係の意味情報が欠落0。ラベルの重なり・線の不正接続・意図しない画像化はCIでFAIL。
- 既存 v0.1 の図・全ベンチマーク3種×3条件を壊さない。
- 例外的SVGの実機編集性は「差し替え可能な画像」であり「内部要素は編集不可」とレポートする。

## 不採用

- ER図を一律にSVGへ変換して完了とする案。
- 高密度図で情報を省略したり、文言を自動書換えして枠に収める案。
- ソースのないAI生成ER画像のみを成果物とする案。
