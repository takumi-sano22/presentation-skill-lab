# ADR-0003: v1.0必須の高密度ER自動分割とPowerPoint追従コネクタ

- 日付: 2026-10-12
- 状態: **Accepted（所有者がQ1=自動分割・Q2=コネクタ追従必須を明示選択）**
- 関連Issue: #32（接続追従）、#33（ER自動分割）、#10（Windows実機Gate 4）、#11（リリース）、#12（進捗）
- 正本の優先順位: このADRはADR-0002の高密度ERの既定SVGフォールバックと、従来の線がノードに追従しない仕様を**v1.0向けに上書き**する。ADR-0001の内容/デザイン分離、元データの保持、決定論的処理は維持。

## 背景・ユーザー判断

Phase 4.5までの生成は、ERの小規模図をネイティブ図形として出力できるが、12エンティティ・43属性・14関係の高密度ER（e403）を単一SVGへ縮小した結果、実効文字サイズが約4.24ptになった。また現行の構成図/ERの線は移動可能な図形ではあるが、ノードを動かすと追従しない。

所有者は次を**v1.0に必須**と決定した。

1. **高密度ERは自動で複数の読みやすい詳細スライドへ分割する。** 元の `content.yaml` は保持する。
2. **PowerPoint内でノードを移動したとき、接続先の線が追従することを保証する。** 構成図とER図の両方を対象とする。

したがって「小さいSVGを警告するだけでCI合格」や「単に接続先へ見た目上の線を置く」だけでは、v1.0の受け入れ条件を満たさない。

## 決定1: 接続追従するネイティブコネクタ

- 図の論理辺は最終PPTXで接続元・接続先の図形IDと接続ポイントを参照する。OOXMLの `p:cxnSp / p:cNvCxnSpPr / a:stCxn / a:endCxn` 等を利用できる。単に`p:sp`のlineに座標だけを与える方法は不可。
- 現行の上流依存 PptxGenJS **4.0.1** に、図形IDを指定して接続する `addConnector()` APIがあることを前提にしない。固定ソース確認→最小PoC→必要な生成後OOXML変換（または同等の実証可能な方式）の順で実装する。独立のパブリックなForkのAPI仕様をそのまま採用したことにしない。
- 接続先ID・サイト番号・始点/終点、同名ノード、並行/逆向き辺、接続線の数・向き、幾何の確認をXMLベースで検査する。図形IDの重複や未接続への退行はCIのFAIL。
- ERではエンティティ枠・名称・属性行を**論理的にまとめて動かせる**必要がある。ただし内部の属性テキスト等は引き続き編集可能にする（ネイティブのグループ等を含むPoCを実施）。接続はFK側と参照先側の正しいエンティティ/ポートに結びつける。多重度や関係ラベルも移動後に見誤らない状態を目指す。
- 折れ線・複数線分は、ノード移動によって端点だけがついてきても中間が取り残される設計では不合格。既存の経路/区画/ラベルとPowerPointの自動再経路の両立を実測し、必要なら接続形状・ルーティング構造を刷新する。
- **Windows PowerPointで実際にノード移動→接続追従→保存→閉じる→再オープンで維持**を確認する。XMLチェックやLibreOfficeの出力だけではGate 4を解除しない。

## 決定2: 高密度ERは単一SVGではなく読みやすい詳細ビューへ自動分割

- デフォルト `auto` は、1枚に安全なネイティブERが収まれば1枚、収まらなければ**複数のネイティブ詳細ページ**を決定論的に構成する。元のER定義・属性・PK/FK・nullable・関係・多重度・参照IDを変更/削除してはならない。
- 1入力スライドが複数の出力ページへ展開される**1:N契約**をadapter、内容照合、PPTX/PDF/PNGページ数、QA、HTMLギャラリー、検証キットまで貫く。各出力ページに安定ID（元IDから生成）と `source_slide_id`、表示したエンティティ/属性/関係の追跡情報を付与し、入力元に逆写像できるようにする。
- 詳細ビューの属性名・型・キー・関係は**全件がページ群のどこかで明確に読める**こと。ページ間に跨がるリレーションは、両端、向き、多重度、別ページ参照を必ず確認できるようにする。文脈ノードの重複表示はよいが、manifestに重複関係を明示する。出典・説明・注記の自動改変禁止。
- 自動グラフ分割は機械的に再現可能なルール（トポロジー/接続/文字幅/密度/安定ID）による。エンティティ数が同じでも属性密度が違えば結果が変わり得る。上限ページ数/探索時間を制約し、成立しなければ**理由付きFAIL**とする。
- 詳細ページの文字は最小9pt未満を不可とし、9pt以上でも実際に読めるかをWindowsと視覚QAで判定する。**4pt程度の縮小SVGを「合格詳細ページ」と扱わない**。概要ページを別に用意する場合も、概要は細部省略が明示されたガイドであり、全詳細を代替しない。
- 旧v0.1/0.2の入力は受け入れ続ける。 `diagram_mode: native` は「ネイティブのみ」の意味を保持し、`diagram_mode: svg` の明示指定は勝手に無視せず、レガシー互換・出力の可読性・概要目的を区別する。既定autoの高密度図を小さいSVGに黙って後退させない。必要な追加フィールドがあればschema-versioning手順による**互換追加**とする。
- 元入力1枚を複数にした結果の文章/セル/関係の一致は、従来の入力・出力1対1比較では不十分。**入力の一意な意味項目と出力全詳細ページのcoverageを照合**し、欠落0、向きや多重度の誤り0、許可した文脈重複以外の改変0を実証する。

## テストとリリースGate

| 条件 | 自動CIでの判定 | Windows実機 |
|---|---|---|
| 接続追従 | 接続ターゲットのshape ID/サイト、全論理辺の一致、未接続の検出 | 実ノードをドラッグし両端が追従、保存後も保持 |
| ネイティブERの移動 | 属性・PK/FK・関係ラベル・図形構造の整合 | エンティティを1単位で移動でき、内容も一緒に移る |
| 高密度ER分割 | e403の詳細ページ複数、全12エンティティ/43属性/14関係のcoverage、文字9pt未満0 | 全詳細ページの文字・関係が読める |
| 元資料の不変性 | content hash不変、Slide ID→派生ページID、旧v0.1/v0.2の入力互換 | PDF/PNG比較、順序の分かりやすさ |
| 安定性 | 同一入力でページ分割/ID/接続先が決定論的、CI既存3デッキ×3条件とGate4-A/B成功 | PowerPointの修復ダイアログなし |

`#32` を先行して実装し、`#33` はその後に進める（レンダラ・build・QAへの競合変更を減らすため）。各IssueはCIの自動DoDを満たせばPRをマージできるが、**Windows実機証跡は#10で人が確認する。実機の失敗があれば修正して再テストし、#11のReleaseを保留する。**

現行 `gate4-windows-kit`（CI run 38155897432、main `0ce0192`）は旧仕様の比較材料にすぎない。**本ADR適用後の正式なGate 4/Release証拠として再利用してはならない**。#32/#33完了後に新しいkitとSHA256SUMSを生成する。

## 停止条件

上流互換性が破れる、PowerPointでコネクタ接続が成立しない、元データの欠落を防げない、意味やスキーマの破壊的変更が必要、CIが誤って緑になる、ライセンスや課金の判断が必要、のいずれかでは安全側で停止し、原因・再現手順と代替案をIssueに残す。**見かけだけの修正でGateを緩めてはならない。**
