# トークンと作業コストの設計

## 低コスト標準レーン

1. 入力リポジトリ・資料の該当範囲だけを参照する。丸ごとコンテキストに投入しない。
2. 内容担当は構成・主張・表データ・出典だけを決める。デザイン指示を混ぜない。
3. デザイン担当は `content.yaml` を読み取り専用とし、再要約せず `design.yaml` のみ編集する。
4. 既存レイアウトと native 図形を優先し、画像生成はカスタムイラストなどに限定。
5. YAML検査・PPTX生成・PDF化・文字/図形検査はローカルスクリプトで処理する。
6. 各修正では変更のあった Slide ID のみ再評価する。完成前だけ全スライドを目視確認。
7. 致命的な違反がある場合だけ LLM QA。サブエージェントを 3 周回す設計はデフォルトで採用しない。

## 計測する指標

- 依頼あたりの使用モデル/回数、概算トークン（取得可能な範囲）、画像生成数。
- スライド枚数あたりのビルド時間、修正回数、検出／未検出のレイアウト不良。
- ChatGPT通常 / ChatGPT Work / Claude Code の再現率と品質を同一デッキで比較。

サブスクリプションの使用枠・API課金は別物。具体的なプランやモデルごとの単価は未検証のため金額保証をしない。
