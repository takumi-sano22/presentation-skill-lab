## C1: ネイティブ接続追従（**v1必須**）

1. Windows版PowerPointで新キットの構成図とER図を開き、基準PDF/PNGと表示比較する。Office版・Windows版・指定フォントと実際のフォント、PPTX SHAを記録。
2. 対象は **構成図のノード**（複数の入力・出力辺を持つもの）、**ERのエンティティ**（属性/PK/FK付き）、**分割ER詳細ページのエンティティ**。PowerPoint選択ウィンドウの図形IDは新キットの `objects.md` を使う。
3. コピーしたPPTXで各ノードを少しドラッグする。**接続していた全辺の両端がノードの移動に追従**し、関係が別ノードへ入れ替わらないこと。ERエンティティは属性・見出しをまとめて移動でき、属性テキストは個別編集できること。
4. 並行辺・折れ線・ラベル/多重度のある箇所も確認。線が一部取り残される、ずれたノードに繋がる、エンティティの属性が置いていかれる場合はFAIL。
5. 色/テキストを変更→保存→閉じる→同じPPTXを再オープンして追従関係が残ること。**PowerPointが修復ダイアログを出したらFAIL**。元ソースの `content.yaml` は操作しない。

## C2: 高密度ER詳細の可読性（**v1必須**）

1. 既存の `examples/bench-er` e403（12エンティティ・43属性・14関係）の**新しい自動分割出力**を対象にする。元 `e403` が生成された複数ページへ展開されたことと、manifestの `source_slide_id: e403` 等の逆写像を確認。
2. 各詳細ページで、**属性名/型/PK/FK・多重度・関係ラベルが判読可能**、互いに重なりなし、線や境界の交差が意味を妨げないこと。細部を読めるページが揃い、元の全関係を追跡できること。概要がある場合は詳細ページとの対応を確認。
3. 旧キットのe403単一SVG（属性4.24pt）は**改善前の比較素材のみ**。旧状態をv1成功と判定しない。文字が極端に小さいページ、全属性が切り捨てられたページ、関係の参照先が分からないページはFAIL。
4. 分割後の**少なくとも2枚**で C1 のノード追従・保存・再オープンを試す。詳細ページがネイティブ編集可能であること。
5. 原sourceとmanifest/coverage reportの突き合わせはCIで行うが、**人間にも意味の分かりやすさを採点**してもらう。

## C3: 従来機能の回帰

現行のキットのタイトル・表セル・グラフデータ・SQL等幅・暗色テーマ・日本語の折返しも新commitで検証。新しいERコネクタやページ展開によって、別のスライドのページID・図形選択名・本文が崩れていないこと。
