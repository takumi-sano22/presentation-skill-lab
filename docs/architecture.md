# アーキテクチャ / v0.1

## 1. ゴールと非ゴール

- ゴール: 文章と見た目を独立管理し、Claude Code / ChatGPT が同じ資料を更新できること。
- ゴール: 技術図、比較表、表、グラフを多用しても日本語で視認性を保つこと。
- ゴール: PPTX 上で文字と表を編集でき、複雑な SVG・写真・イラストだけ画像として許容すること。
- 非ゴール: PowerPoint が HTML/CSS や SVG の全機能をネイティブ編集できるようにすること。
- 非ゴール: 任意の PPTX / PDF を完全可逆に JSON 化すること。
- 非ゴール: 特定の LLM プロバイダーへ依存すること。

## 2. データフロー

```text
ChatGPT / Claude Code / GitHub の資料 / 会話
          │
          ▼
   content.yaml + data/*.csv
   (本文/表/意味上の図/出典/固定ID)
          │                 design.yaml + assets/*
          └──────────┬───────────┘
                     ▼
       adapter / normalizer [Phase 1]
          → vendor/presentation-skill の outline.json
                     ▼
           PptxGenJS native PPTX
                     ▼
           PDF / PNG / HTML preview
                     ▼
        schema → geometry → content → visual QA
```

`outline.json` はレンダラ専用の **生成物**。編集しても次回ビルドで失われる。`content.yaml` と `design.yaml` だけを編集する。

## 3. ソース分離契約

### content.yaml（内容担当）

- `deck_id`, audience, objective, classification, `synthetic`。
- 各 `slide.id` は変更・移動しても維持する安定 ID。
- `title`, `takeaway`, `body`, `table`, `diagram` 等の情報内容。
- 数値、単位、表セルはレンダラが勝手に短縮・要約・捏造しない。
- `source_refs` は参照可能な一次資料、URL、コミット等を記載。
- 文言修正は `content` レーンでのみ実施。

### design.yaml（デザイン担当）

- デッキ全体のテーマ、配色、フォント。
- スライド ID ごとのレイアウト、密度、図形モード、必要なアセット。
- 文言・数値・テーブルセルを書き換えるフィールドは持たない。
- 改善が内容変更を必要とする場合は提案し、内容担当の承認を得る。

### ビルド時の保護

- レンダラ入力の前後でテキスト、表セル、グラフの数値を正規化してハッシュ化し、欠落・変化を差分で検出。
- 可読性上の問題がある場合、デザインの調整・スライド分割の提案を優先。
- スライド削除・統合・数字の丸め・語句の変更は自動実行しない。

## 4. 図のレイヤー（Phase 3）

| 種類 | ソース | 出力方針 | PowerPoint編集 |
|---|---|---|---|
| アーキテクチャ・フロー | nodes / edges の構造化データ | Dagre 等で配置、PptxGenJS ネイティブ図形 | ノード・文字・線を編集可能にする |
| 比較表・マトリクス | 構造化セル、CSV | ネイティブ表/テキスト | 編集可能にする |
| 棒・折線等の基本グラフ | 生データ+描画属性 | PowerPoint ネイティブ Chart | 編集可能にする |
| ER図 | テーブル定義＋関係 | v1は SVG と元データ保存、将来ネイティブ図形 | v1は画像、元ソースから再生成 |
| 独自イラスト・複雑な図 | SVG/PNG + 元プロンプト | 高解像度画像 | 画像として編集／差替可能 |
| HTML/CSS カスタム図 | HTML ソース + Playwright | SVG/PNG変換して配置 | v1は画像 |

接続線は「ノードID間の依存」「接続ポート」「レイヤー内の経路」を明示し、任意の位置へ LLM が自由な座標を書かないことを原則とする。交差・ノード重なりを検査する。描画の再現性を優先。

## 5. 日本語の可読性（初期基準、今後調整）

- 標準は16:9、タイトル26–34 pt、本文16–22 pt。
- 密度の高い技術表、コードは12–16 ptを例外として許容し、注釈で理由を残す。
- 行高さ/字間/折り返し/単位表記/和欧混植/フォントフォールバックを検査。
- デフォルトは Noto Sans JP（インストール環境での互換性を要確認）。
- 固定下限よりも「スライドの役割と閲覧距離」に基づき QA プロファイルを選ぶ。

## 6. QA レーン

1. `schema`: JSON Schema / Slide ID / 内容⇔デザイン対応 / asset path。
2. `content`: 数値・単位・文言保持率、プレースホルダー、出典参照。
3. `geometry`: はみ出し、図形重なり、接続線、罫線、余白、文字サイズ。
4. `visual`: 全ページレンダリング後、目視＋必要時だけ LLM 視覚レビュー。
5. `editability`: PPTX XML のオブジェクト型検査（テキスト／表／チャートが画像化されない）。
6. `reproducibility`: 同一入力・依存コミットの正規化出力およびレンダリング安定性。

**Gate:** 重度のはみ出し 0、欠落した数値/単位/表セル 0、未承認の内容改変 0、公開リポジトリの秘密情報混入 0。既知の誤検知を無視する場合は例外理由と対象 Slide ID を記録。

## 7. 依存アップグレード

上流は固定コミットを参照し、変更は専用 PR で行う。差分確認→ライセンス確認→サンプル回帰→PPTX描画比較→承認→反映。直接 main へ upstream を自動追従させない。
