# 実装計画：Issue に切り出す順序

各 Issue の番号は、GitHub に登録後に採番する。元原稿は [`docs/issues/`](issues/) にあり、`scripts/create-issues.sh` でまとめて登録する。Phase/Gate を守り、ユーザー判断待ちの条件は人が解除する。

| Phase | Issue案 | 完了条件 (DoD) | 前提 |
|---|---|---|---|
| 0 | リポ初期化と方針の正本化 | MIT、ADR、skills、schemas、CI、合成サンプルが main に存在し `validate` が PASS | この雛形 |
| 1 | upstream バージョン固定・セットアップ | `siril9/presentation-skill` の SHA を記録、ライセンス保全、doctor が通る | 0 |
| 1 | content/design → outline.json adapter | JSON Schema と変換テスト、文字・数値欠落0、再実行で正規化出力安定 | 1-基盤 |
| 1 | PPTX/PDF/PNG出力コマンド統一 | 5枚以上の日本語デッキを同じコマンドで生成できる | 1-adapter |
| 2 | 日本語デザイン規約とテーマ | technical-light / technical-dark、タイトル/表/脚注の和文検査 | 1 |
| 2 | 表・グラフ・比較レイアウト | CSV、単位、表値保持。PPTXのテキスト/表/グラフが編集可能 | 2-テーマ |

## Gate

- **Gate 0（方針）:** 完了。この ADR とスキーマ v0.1 を開始基準とする。
- **Gate 1（最小生成）:** 5～8枚の日本語技術資料がコンテンツを変えずに PPTX/PDF 生成される。
- **Gate 2（編集可能性）:** テキスト・表・基本チャート・ネイティブ図形が PPTX オブジェクトとして残る。例外画像は一覧化。
- **Gate 3（QA）:** 技術図、比較表、密な日本語の3セットで重大崩れ0かつ内容欠落0。
- **Gate 4（運用）:** Claude Code と ChatGPT 双方から同じソースを修正でき、ライセンスとトークン使用量を記録できる。

## 初期ベンチマーク

1. **アーキテクチャ図:** Azure/Snowflake連携の架空構成。境界・多段矢印・注釈。
2. **表とグラフ:** 合成データ 4項目、比較表・棒グラフ・条件付き注記。
3. **密な技術資料:** ER図+コネクタ・SQL/コードブロック・CJK折返し。

各セットで、6～10枚を目安に構成し、初回とテーマ変更後の見た目を評価する。**実際の顧客/業務データは使わない。**

## 方針変更の判断点

Gate 2 で editability と描画再現性の両立が継続してできない場合のみ、Slidev `pptx-editable` または別レンダラを比較。いきなり二系統運用にしない。
