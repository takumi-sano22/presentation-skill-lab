# Gate 4: Windows 版 PowerPoint 実機検証の手順（#10）

> **注意（2026-10-12）:** 本文の7デッキ/固定線/e403単一SVGを前提とする旧キットの項目は**比較用ベースライン**です。v1.0正式判定では [ADR-0003](decisions/0003-v1-readable-er-and-attached-connectors.md) および [新Gate 4必須項目](gate4-v1-acceptance.md) が優先し、#32のノード移動追従と#33のER詳細自動分割を実装した**新しいコミットのキット**で確認します。既存run 38155897432だけではv1.0 Gate 4を解除できません。

対象コミット: `{{COMMIT}}`

この手順は**人が Windows 版 PowerPoint で実施する**。Claude Code / CI は LibreOffice で描画した PDF・PNG と PPTX の XML までしか確認しておらず、PowerPoint 実機での表示・編集・保存は**未実施**である。結果は #10 にコメントで記録する（テンプレートは末尾、キットでは `RECORD_TEMPLATE.md`）。

## 0. キットの入手

1. GitHub Actions の main の最新 run（Validate sources）を開き、artifact **`gate4-windows-kit`** をダウンロードする（または WSL で `scripts/dev.sh run python3 scripts/gate4_kit.py` を実行し `build/gate4-kit/` を使う）。
2. `kit.json` の `commit` と、`SHA256SUMS` の値を記録に写す（どの PPTX を検証したかを特定するため）。
3. 元の PPTX は残し、検証は**別名で保存したコピー**に対して行う（例: `deck-win-edit.pptx`）。PowerPoint で編集した PPTX を正本（content.yaml / design.yaml）へ戻さない。

| フォルダ | 観点 |
|---|---|
| 01-claude-content-light | 基本: 表・棒グラフ・ネイティブ構成図・長い日本語見出し |
| 02-claude-content-dark | 暗色テーマ（見出し帯・表・図の配色） |
| 03-gate4a-chatgpt-design | Gate 4-A: ChatGPT が design だけ変更 |
| 04-gate4b-chatgpt-content | Gate 4-B: ChatGPT 作成の content に Claude Code が design |
| 05-er-native-and-svg | ER: e402 ネイティブ（個別編集可）、e403 SVG 例外（図全体の画像） |
| 06-dense-tech | 表紙の改行、SQL の等幅列、v0.1 の ER |
| 07-table-chart | 比較表・1系列棒グラフ（単色）・折れ線グラフ |

各スライドで編集を試す図形の名前は `objects.md` にある（PowerPoint の［ホーム］→［配置］→［オブジェクトの選択と表示］で選択ウィンドウを開くと同じ名前が表示される）。

## 1. 環境の記録

- Windows のバージョン、PowerPoint のバージョン（［ファイル］→［アカウント］→［PowerPoint のバージョン情報］）、Microsoft 365 / 買い切りの別。
- フォント: **Noto Sans JP** がインストールされているか（［ホーム］でタイトルを選択しフォント名欄を見る。代替されると斜体や別名で表示される）。等幅列の **Consolas** は Windows 標準。フォントファイルは公開リポジトリにアップロードしない。
- 代替が起きた場合は「指定フォント → 実際に表示されたフォント」を記録する（改行位置・はみ出しの差の原因になるため）。

## 2. 表示の確認（PDF/PNG との比較）

各デッキを開き、同じフォルダの `deck.pdf`（または `png/`）と全ページを見比べる。

- [ ] 文字の欠け・はみ出し・重なりがない（特に長い日本語見出し、表のセル、図のラベル）
- [ ] 表紙タイトル（06 の d301）が「受注データの関係と／整合性検査を共有する」の2行で、最終行が1〜3文字だけにならない
- [ ] 図のノード名・辺ラベル（01 の s003、06/05 の ER）の改行位置が PDF と同じ（明示改行のため、フォントが同じなら一致するはず）
- [ ] 矢印の向き・線種（実線=データ、破線=制御）が PDF と同じ
- [ ] 暗色テーマ（02）の見出し帯が背景と区別できる
- [ ] 1系列の棒グラフ（07 の c203、01 の s005）が単色
- [ ] SQL の列（06 の d303）が等幅書体
- [ ] ER の SVG 例外（05 の e403）が表示される（PowerPoint 2016 以降は SVG、古い版は PNG 代替）

## 3. 編集・保存・再オープン

別名保存したコピーで、次を**1つずつ**編集し、保存 → 閉じる → 開き直して編集が残っているかを確認する。

1. **タイトル文字**: 任意のスライドのタイトルを1文字変更。
2. **表のセル**: 01 の s004 の任意のセルの文字を変更。行・列の追加ができるか。
3. **グラフのデータ**: 01 の s005（または 07 の c203）のグラフを選び［グラフのデザイン］→［データの編集］で値を1つ変更し、棒の高さが変わるか。
4. **構成図のノードと線**: 01 の s003 で `node:agent` の文字を変更し、ノードを少し移動。`edge:` の線を選択して色・太さを変更。
   - 注: 線は「直線図形」で、ノードに接続（コネクタ）されていない。ノードを動かしても線は追従しない（既知の仕様）。この挙動を記録する。
5. **ER（ネイティブ）**: 05 の e402 で
   - エンティティ名（`er-entity:item`）の文字を変更
   - 属性行（`er-attr:item:1`「PK 明細番号 : INT」）の文字を変更し、行を追加するなら同じ枠内に新しいテキストボックスを置けるか
   - 多重度（`er-card:0:from`「1..N」）を変更
   - 関係線（`er-edge:...`）を選択して色を変更
6. **ER（SVG 例外）**: 05 の e403 で `er-svg:e403` を選択し、**図全体が1つの画像として選択・移動・サイズ変更できる**こと、**内部の文字・線は個別に編集できない**ことを確認する（これが正しい挙動。［グラフィックス形式］→［図形に変換］で分解できる場合も、正本は content.yaml であり分解後の編集は正本に戻らない点を記録する）。
7. **等幅列**: 06 の d303 の SQL セルを編集し、等幅のまま入力できるか。

## 4. 人による装飾評価（5段階）

1=致命的な崩れ、3=実務前に修正したい、5=手直し不要。Claude の自己評価（docs/benchmarks.md）とは**別に**記録する。低い点はスライド ID と原因の見立てを書く。

- 見出し（長い日本語・改行・帯）
- 和文の文字組み（改行位置・禁則・行間）
- 図の意味（矢印・線種・ER の多重度）
- 表・グラフ（列幅・余白・配色）
- 余白・配置

## 5. 記録と判定

- FAIL があれば、スライド ID・操作・期待と実際・PowerPoint のバージョンを書く。Claude Code 側で直すときは別 Issue にする。
- #10 の Close と #11（v1.0 リリース判定）は、所有者が本記録を確認して承認してから行う。
