# 日本語スライドの初期規約

> 将来の実用デッキのレビューから少しずつ追加する。最初から数百条に膨らませない。

1. **中身を守る:** 数値、単位、比較方向、因果関係、前提条件、用語をデザイン作業で変更しない。
2. **結論を可視化:** 技術資料ではスライド見出しに主張や問いを置く。アーキテクチャ図は「何の構成か」が一目で分かるラベルを持つ。
3. **意味上のグループ:** 認証／入力／処理／保存／出力を区画で分ける。近接と囲いで意味を示し、装飾だけの枠を乱用しない。
4. **矢印の意味:** 矢印には伝達・依存・制御・同期などの種類を持たせる。単なる飾りとして追加しない。
5. **可読性:** タイトル/本文/図中ラベルを別々のフォントサイズ基準で検査。例外は記録し、読めない密度なら分割を提案する。
6. **表の誠実さ:** 単位・期間・比較対象を明示。桁丸め、欠落、セル結合、順序変更は内容担当の了承を得る。
7. **色の意味:** 成功/注意/エラー等の色は同一資料で意味を統一し、色だけに依存しない。
8. **LLMの過剰装飾を防ぐ:** 不必要な3カード横並び、意味のないアイコン、細かい脚注の乱用を避ける。
9. **プレビュー:** PDF/PNGで全ページ確認し、生成PPTXの一部を実PowerPointまたは互換表示で確認する。
10. **一般化:** レイアウト事故は「その1枚の修正」で終わらせず、再現サンプルと検出ルールを追加する。

## 日本語テーマ規約（technical-light / technical-dark）

`design.yaml` の `theme` だけで見た目を変える。content.yaml は変えない（同一 content の light / dark ビルドで `content_sha256` と意味項目が一致することをテストで担保）。
自動検査できるものは `scripts/adapter.py`（配色）・`scripts/build`（組版）で検査し、manifest の `checks` に記録する。

| ID | 規約 | 適用条件 | 例外・扱い | 検査 |
|---|---|---|---|---|
| J-1 | 最小文字サイズ: タイトル 26pt、本文 16pt、補助 12pt、キャプション 10pt、フッタ・メタ情報 9pt、タイトルは2行まで | 全スライド | 密な技術表・コードは 12pt まで可（`docs/architecture.md` §5）。上流の読みやすさ契約（`readability_contract`）として渡す | 上流レンダラが適用 |
| J-2 | タイトルは全角換算 40 字以内を目安（半角は 0.5 字） | 全スライド | 40 字超は WARN、80 字超は FAIL。短縮は内容担当が判断（デザイン側で文言を変えない） | `checks.japanese_*` |
| J-3 | 泣き別れ禁止: 折り返したタイトル・要点の最終行を 3 字以下にしない | タイトル・要点 | WARN。表紙は幅の広いレイアウト（light-atlas）を使って防ぐ。直らない場合は内容担当が語の切れ目を見直す | `checks.japanese_warnings` |
| J-4 | 書体は見出し・本文の 2 書体まで。欧文・和文とも design のフォント名を PPTX に書く | 全スライド | 描画環境では fontconfig の別名で解決（Noto Sans JP → Noto Sans CJK JP）。記号の代替フォント（OpenSymbol）は許容 | PDF 埋め込みフォント検査・描画契約テスト |
| J-5 | 配色コントラスト: 本文・補助文字は背景に対し 4.5:1 以上、表ヘッダ（太字の白）とアクセント面 3:1 以上、図形（グラフ・罫線）は背景に対し 3:1 以上 | テーマ全体 | 満たさないテーマは `DesignError` で FAIL | `scripts/adapter.py` |
| J-6 | 色はデザイントークンだけで決める（背景・前景・アクセント・補助）。濃色面は背景と前景の暗い方、第2アクセントは補助色 | テーマ全体 | 上流プリセット固有の色を残さない。グラフの軸・凡例文字も補助色にする | 描画契約テスト |
| J-7 | 表とグラフは PowerPoint のネイティブオブジェクトで作る。画像化しない | 表・グラフ | — | PPTX 内の表・`ppt/charts/` を検査 |
| J-8 | 同じ指標は全ページで値・単位・丸め桁を揃え、数え方と単位を混ぜない | 内容担当 | 内容レーンの規約。デザインでは数値・単位を変えない | adapter の往復検査（変更の検出） |

### 採用しなかった規約（理由）

- 「サブタイトル・説明行の全面禁止」: 本プロジェクトは content.yaml の `takeaway`（要点）をタイトル下に表示する契約のため採用しない。
- 表の「背景塗りなし・ゼブラ禁止」等の細かな罫線指定: 上流レンダラ v0.14.0 の表スタイルを外から細かく制御できないため、現時点では採用しない（#8 の QA で必要性を再評価）。
- 「本文が版面の 55% 以上」: 幾何 QA（#8）で扱う。
