# 日本語スライドの初期規約

> 将来の実用デッキのレビューから少しずつ追加する。最初から数百条に膨らませない。

1. **中身を守る:** 数値、単位、比較方向、因果関係、前提条件、用語をデザイン作業で変更しない。
2. **結論を可視化:** 技術資料ではスライド見出しに主張や問いを置く。アーキテクチャ図は「何の構成か」が一目で分かるラベルを持つ。
3. **意味上のグループ:** 認証／入力／処理／保存／出力を区画で分ける。近接と囲いで意味を示し、装飾だけの枠を乱用しない。
4. **矢印の意味:** 矢印には伝達・依存・制御・同期などの種類を持たせる。単なる飾りとして追加しない。
5. **可読性:** タイトル/本文/図中ラベルを別々のフォントサイズ基準で検査。例外は記録し、読めない密度なら分割を提案する。
6. **表の誠実さ:** 単位・期間・比較対象を明示。桁丸め、欠落、セル結合、順序変更は内容担当の了承を得る。
7. **色の意味:** 成功/注意/エラー等の色は同一資料で意味を統一し、色だけに依存しない。
8. **LLMの過剰装飾を防ぐ:** 不必要な3カード横並び、意味のないアイコン、細かい脚注の乱用を避ける。
9. **プレビュー:** PDF/PNGで全ページ確認し、生成PPTXの一部を実PowerPointまたは互換表示で確認する。
10. **一般化:** レイアウト事故は「その1枚の修正」で終わらせず、再現サンプルと検出ルールを追加する。
